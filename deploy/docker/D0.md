# Docker D0: candidate freeze and gates

Status: candidate frozen; **not fully passed**, not a runnable distribution.

`runtime-lock.json` pins source identity, Python/Node image index and per-architecture digests,
executor versions and official artifact hashes. `acceptance-matrix.csv` contains the 12 unverified
host/executor cells. macOS native completion does not close any container cell.

Verified in disposable containers: Python 3.11.15, glibc 2.36, UID/GID 1000,
Unicode/space path and atomic replace on arm64 and emulated amd64; Node 22.23.2 arm64.
Downloaded arm64 Codex/OpenCode archives match official SHA256 and print their expected versions.
Codex must use its full official package with companion resources; the bare CLI lacks bwrap.
With official bwrap available, `codex sandbox linux -- /bin/true` fails to create a namespace
under the tested nonroot/cap-drop/no-new-privileges configuration. No privileged or unconfined
fallback was tried. This blocks certification of that sandbox combination, not all container work.

Freeze: one glibc Linux image family; separate nonroot Runner and WebUI services using one image.
Runner reads `/home/agentbc/.abc/config.toml`; state at `/data/workspace/record`, reports at
`/data/workspace/tasks/report`, artifacts at `/data/workspace/tasks/artifacts`; WebUI mounts only
record/report read-only at identical absolute paths. `/project` is the explicitly chosen customer
bind; `/input` is read-only. `/run/agentbc` is ephemeral Runner spool/token and never mounted by WebUI.
Credential/session storage is private, per instance and executor; no host home or docker.sock mount.
UID/GID default 1000; explicit Linux mapping and volume initialization must not recursively chown
existing user projects. Default fixed port is selected by the host setup and persisted, not guessed
from within a container. WebUI publishes only 127.0.0.1 and uses its own token.

Open gates: actual four-executor Linux authentication; complete Claude SDK transitive lock and
actual two-architecture installs; SDK/native CLI compatibility; Codex namespace sandbox; native
amd64 acceptance; redistribution permissions for proprietary binaries. No automatic credential
copy, SDK upgrade, mode change or host kernel change is authorized by this freeze.

D1 may build the isolated OpenCode vertical slice against this candidate, but cannot claim D0 fully
passed or release readiness. D2 must resolve applicable sandbox and approval gates without weakening
existing three-agent contracts. Candidate sources are reproducibility inputs, not proof of support.
